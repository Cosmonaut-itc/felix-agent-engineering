## B-W1: SIGINT entre claim y spawn

El dispatcher de submit/recover instala el diferidor **antes** de la transacción de
claim. SIGINT manejado queda registrado en memoria; no interrumpe commit, Popen ni
la espera de readiness hasta10s. Se restaura el handler y se plantea KeyboardInterrupt
al salir de esa frontera. CLI responde130/client_interrupted; la admisión puede estar
confirmada aunque se pierda su recibo. Consultar K; no reenviar otra clave.

Si Popen del supervisor falla inequívocamente antes de crearlo, el launcher original
registra never-created, cierre/permiso cerrado y expediente antes de propagar la
interrupción. Si se creó supervisor, sólo éste puede vincularse y consumir permiso.
EOF/timeout de readiness no prueban no creación: starting conserva reserva y puede
dar3. El SIGINT diferido no salta desde claim directamente a una salida del cliente
antes del intento de lanzamiento. Errores de almacenamiento aún pueden impedir
acreditar cierre; entonces se retiene. No se promete rescatar SIGKILL, SIGHUP no
manejado, fallo abrupto del sistema o cada syscall Popen.

El test B-W1 escribe una campaña CLI acotada con procesos propios y estado/vínculo
públicos registrados. **La ventana exacta pre-spawn no está validada**: un snapshot
starting/unbound no permite distinguir Popen todavía no ocurrido de creación sin
vínculo. No se reemplaza ese requisito por una señal posterior a running ni se
introducen hooks privados. El padre deberá conservar este límite en validación.

## B-W2: binding operatorio atómico, sin pending durable local

Las4 acciones mutantes autentican actor nativo y owner/privacidad del estado. Bajo
una única transacción leen secretos persistidos y deciden petición/binding, prueba,
control/capacidad, recibo y auditoría. Motivo inválido por forma se rechaza sin
reflejarlo; motivo/ID con credencial conocida produce rechazo saneado auditado sin
crear binding operativo. No se acepta identidad de env/flags como actor.

| Frontera | Estado durable / recuperación explícita |
| --- | --- |
| Antes de commit o rollback confirmado | No operation-id persistido; status not_found acotado a revisión. No implica ausencia futura concurrente. |
| Commit confirmado | Binding completo y receipt committed, incluso rechazo atribuible; no intención intermedia. |
| ACK/stdout perdido | Status muestra receipt; repetir petición exacta devuelve binding=replay. Otra petición5, no modifica original. |
| Commit no acreditado | Error3/effects unknown; consultar después. La atomicidad impide release/control sin su auditoría dentro del ledger cooperante. |
| Caída durante transacción | SQLite confirma todo o rollback; sin autoridad para inferir cuál desde el cliente muerto. |
| Recover ordinario | operator_pending=[] porque no existe intención durable local; sólo informa decisiones ya confirmadas, sin continuar verbos. |

No existe blocked_by operator_resolution_pending en este backend: la exclusión y
commit atómico evitan una reserva públicamente liberada con intención durable sin
decisión. Durante transacción un lector espera lock; después observa antes/después.
Lock/lectura fallidos no inventan pending ni capacidad libre. Este refinamiento no
pretende aplicar atomicidad local a hostgate o transporte futuros.

Drain corta cada claim, incluido el encadenamiento ordinario del supervisor; no mata
carga. Assess sólo es elegible con cuerpo/cierre originales y gate cerrado. Prueba
liga autoridad/uid/job/attempt/reserva/generación, epoch/drain, revisión relevante,
identidad nativa del verificador y digest. Release repite guardas bajo la exclusión
común y registra capacidad+resolution+decision+audit atómicos. Reopen es otra acción
nueva, exige capacidad reconciliada, mantiene la historia y no despacha.

Precedencia: actor/estado/forma → binding replay/conflict → job/attempt/backend →
reserva/generación → drain/época → proof/integridad/vigencia/cierre. Nueva petición G
con H posterior da generation_mismatch5 aunque proof G sea antiguo. Already_released
sólo para misma asignación libre sin generación posterior; replay viejo sólo historia.
Already_drained0 conserva drain-id; ausencia de drain activo not_drained3; drain-id
viejo frente a época activa drain_mismatch5. Una prueba original terminal estable
con permiso cerrado no adopta ni penaliza otro proceso que reutilice el PGID numérico:
se revalida su cadena durable, no se usa un killpg tardío como identidad de G.
